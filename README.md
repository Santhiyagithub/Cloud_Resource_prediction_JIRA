## Project Overview

This project builds an end-to-end **Cloud Resource Usage Prediction and Cost Optimization** system using Machine Learning. It predicts the next-step CPU utilization of a cloud workload using recent resource usage history, and provides actionable capacity-planning recommendations.

**Live Demo:** [Hugging Face Space](https://huggingface.co/spaces/Santhiya08/cloud-resource-prediction)

## Dataset

> ⚠️ **Disclosure:** This project uses **synthetic data** generated by `make_data.py`.  
> The dataset simulates realistic CPU, memory, and network utilization patterns using  
> sinusoidal oscillations with Gaussian noise. It was generated because no suitable  
> real-world dataset was available within the project deadline.  
> Results should not be interpreted as real-world cloud cost-savings evidence.

Dataset: `data/cloud_data.csv` — 3,000 timestep rows with columns:
- `timestamp` — integer time index
- `cpu` — CPU utilization (%)
- `memory` — Memory utilization (%)
- `network` — Network utilization (normalized 0–100)

## Setup and Installation

### 1. Clone the repository
```bash
git clone https://github.com/Santhiyagithub/Cloud_Resource_prediction_JIRA.git
cd cloud-resource-prediction
```

### 2. Create and activate a virtual environment
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

---

## Running the Project

### Step 1 — Generate synthetic data
```bash
python make_data.py
```

### Step 2 — Train the model and log to MLflow
```bash
python train.py
```

### Step 3 — View MLflow experiment results
```bash
mlflow ui --host 127.0.0.1 --port 5000
```
Open [http://127.0.0.1:5000](http://127.0.0.1:5000) in your browser.

### Step 4 — Run the Gradio app locally
```bash
python app.py
```

### Step 5 — Run unit tests
```bash
pytest tests/ -v
```

## Capacity-Planning Recommendations

| Predicted CPU | Level | Recommended Action |
|---|---|---|
| < 30 % | 🟢 Low | Scale down idle instances to reduce cost |
| 30–75 % | 🟡 Moderate | Maintain capacity; set auto-scale triggers at 80% |
| > 75 % | 🔴 High | Scale out or investigate the spike immediately |
